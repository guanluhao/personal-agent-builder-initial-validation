# 空白构建器图形界面实施计划

## 目标体验

1. 打开本机界面时没有预选项目或预设 Agent。
2. 用户拖入 Python 项目文件夹或 ZIP；程序把文件复制到独立导入区，只读扫描并展示《项目能力说明》。此阶段绝不运行导入代码。
3. 界面列出由 AST 识别的简单 `argparse` 入口、参数和证据等级。用户选择能力、提供测试参数并明确确认执行项目副本后，才生成 Agent。
4. 对生成的 Agent 做低成本真实调用；展示调用结果、文件与验证状态。聊天界面继续接收自然语言并调用已注册工具。
5. 新能力仍登记升级请求，不自动改动原项目或启用未测试的代码。

## 技术边界

- 采用仅绑定 `127.0.0.1` 的本地浏览器界面，浏览器提供拖放和聊天体验；不部署公网服务。
- 导入限制文件数量、大小、扩展名和路径；拒绝符号链接、凭据和穿越路径。分析只读、不导入模块、不运行安装脚本。
- 自动候选只覆盖结构清晰的简单命令入口；复杂 Python 程序会给出报告和“需要适配”的结论，不能虚称已生成可用 Agent。
- 项目代码执行没有操作系统级沙箱，因此测试和后续调用必须由用户明确批准；正式隔离仍是后续工作。

## 验证顺序

1. 用全新空白会话导入 CSV 测试项目，确认分析前没有任何预设能力。
2. 在确认前检查没有项目代码执行；确认后生成 Agent，实际汇总三行 CSV，并从聊天界面显示 JSON 文件。
3. 用二维 V1 项目检查可识别候选，但保持轻量预览边界。
4. 验证错误路径、敏感文件、超限上传、无确认生成、未注册功能和关闭服务。

## 已执行的界面验证（2026-10-16）

- 隐藏窗口启动器 `start_app.vbs` 已实际启动本机服务；浏览器初始显示“尚未生成”，没有预设能力。
- 在应用内浏览器通过 ZIP 选择器导入 CSV，页面显示 1 个 Python 文件和 1 个候选；勾选、确认后生成 `csv_project-agent`，测试返回 3 行、总和 10 和真实 JSON 文件。聊天输入中文“请汇总 CSV 中的 amount 列”后，再次调用并生成新 JSON 文件。
- 通过 ZIP 导入二维 V1，页面显示 6 个 Python 文件和 `preview`、`move_anomaly` 两个候选；只选 `preview` 并确认后，真实输出 4 张 PNG 和 4 张 SVG。
- 通过“选择文件夹”导入 CSV 项目，报告再次识别 `csv_task`。点击“关闭应用”后服务停止，运行状态文件删除；演示 Agent 已移到忽略提交的本地证据目录，重新打开界面显示空白。
- 自动接口测试覆盖：初始 Agent 列表为空、无令牌拒绝、路径穿越拒绝、未确认生成拒绝、真实 CSV 生成与聊天、结果文件读取。实际拖放手势尚未单独自动化测试；文件夹选择器和 ZIP 选择器已走通相同导入后端。
- 完整项目回归最终为 **9 passed in 7.26s**；新目录中同名命令脚本的候选名测试也已通过。

## 课程展示视觉改版（2026-10-16）

- 首页加入“代码到 Agent”的抽象示意、四步进度与更明确的导入入口。图形只是流程说明，打开时仍无预装项目或 Agent。
- 能力说明、候选工具、用户确认和聊天结果使用统一的视觉层级；导入、理解、确认、使用的步骤状态跟随实际界面切换。按钮生成期间显示忙碌状态，切换到聊天时回到页面顶部。
- ZIP 内文件平铺时，用 ZIP 文件名为生成的 Agent 命名，避免在课程演示中出现随机导入编号；名称只接受安全的短字符并经过规范化。
- 聊天区根据已注册能力提供可点击的示例提问，只填入输入框，不会自动执行。
- 保留原有安全提示、确认门槛、真实测试标记与失败状态。视觉优化不代表扩大了自动适配范围。
