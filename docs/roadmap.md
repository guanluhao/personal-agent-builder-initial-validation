# 后续扩展路线图

1. **安全隔离**：在容器或低权限账户中运行用户项目，限制 CPU、内存、磁盘和网络；当前仅有应用层白名单、路径检查与超时。
2. **能力自动发现**：目前 AST 已识别简单 `argparse` 参数和命令入口；后续识别复杂 CLI、配置模型与测试，生成候选输入输出 Schema，再由用户确认。当前仍需人工审查工具清单。
3. **持久对话**：用官方 Codex Python SDK 或 app-server 保留线程状态、流式事件和审批；当前 CLI 路由按请求调用，Agent 用本地上下文保存最近配置。
4. **通用代码升级**：接入格式保持的 LibCST 和受限代码修改任务；对每项改动做差异审查、回归测试、版本快照与审批。当前升级机制只在轻量样例完成暂存、测试、启用与回退验证，不代表任意新需求都可自动实现。PDF 已按用户要求退出交付范围。
5. **科研验证**：在用户服务器环境按原仓库规则做资源检查与短基准，再决定是否运行二维正演；网格收敛、边界和成像精度需单独验证。完整 RTM、三维和 V2 不在本轮范围。
6. **交付与分发**：私人 GitHub 仓库已建立并核验；后续增加 CI、版本发布与可复现依赖锁定。
7. **从需求直接生成 Agent**：按“明确探讨清单”中商定的方向，未来可从用户描述的问题出发，在没有现成程序时规划工具、开发代码、自动测试并生成专属 Agent。当前只验证了“已有 Python 项目 → 能力说明 → 用户确认 → Agent”，不能把这一步写成现有功能。
