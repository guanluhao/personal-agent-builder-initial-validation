## 01｜为什么做这个项目

> 做科研时，明明能说清想要什么模型，却要把需求翻译成参数；图片不合适，又得反复改、反复运行。这个项目希望让 Agent 接手这段重复工作。

画面：简洁问题卡片。以上是项目目标，不作为当前“任意描述都能自动建模”的已实现声明。

## 02｜从空白工作台开始

> 打开构建器，工作台是空白的，没有预装某个行业的智能体。
>
> 拖入 Python 项目后，它先读代码和说明，寻找能调用的功能。找到入口，也不会马上生成 Agent。

画面：本地空白首页、项目导入区的真实截图。

## 03｜先理解，再动手

> 它先用通俗的话解释：程序做什么、要什么输入、会产生什么结果。仅凭源码发现的能力会标为推测，不能冒充已经验证。

画面：CSV 项目的能力说明真实截图，突出“仅源码推断”；此处不显示“验证通过”。

## 04｜范围由使用者确认

> 接着由使用者勾选能力并确认。确认前只读分析；确认后才复制项目、生成工具并测试，原程序仍然保留。

画面：真实能力勾选与确认页。不要把勾选前的候选显示成测试通过。

## 05｜先看表格智能体

> 刚才导入的，是一份普通的 CSV 表格程序。构建器找到数值列汇总入口，经确认和测试，生成表格 Agent。

画面：CSV 能力候选与生成成功页。

## 06｜表格智能体真的调用了程序

> 对它说“汇总金额列”，Agent 就调用原程序处理表格。示例只有三行，总和是十，还会写入 JSON 文件。换个说法再问，它仍会实际调用，不是猜答案。

## 制作边界

- 此稿由用户修订后用于新版配音；后续修改应同步字幕和真实画面，不把未测试能力写成现有功能。
- “任意自然语言模型描述自动构建任意抽象模型”是目标；当前证据支持二维 V1 轻量预览、单网格异常点按米移动，以及单独二维隧道示意配置向右延长十米并重新绘图。删减检波点尚未实现，不在此次演示中称为现有能力。
- 结尾展望依据“明确探讨清单”对话中的既定路线：现有代码生成 Agent、需求驱动的修改与升级、最终走向只有用户意图也能构建 Agent。后两层在视频中均作为未来方向陈述，不称为当前已验证能力。
- 早期图形界面这轮只批准 `preview`；按米移动与延长隧道来自后来生成的独立 Agent 测试。两个证据场景必须在视频里区分。
- 旧版成片的配音与内容对应关系被用户否定，仅保留为历史草稿，不作为课程最终成片。

## 说话节奏提示（不进入字幕）

- 开场像向朋友解释一个麻烦：在“翻译成一串参数”后短停，“图不合适”稍微放轻，别像读广告口号。
